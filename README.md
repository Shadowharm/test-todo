# День за днём

Небольшой планировщик на React, TypeScript и Vite, выполненный как тестовое задание: добавить задачу, отметить выполненной, удалить и сохранить результат после обновления страницы.

[Демо](https://test-todo-lyart-psi.vercel.app/) · [Репозиторий](https://github.com/Shadowharm/test-todo)

Статус публикации и результаты проверки: [docs/verification.md](docs/verification.md).

## Запуск

Нужен Node **22.18.0** (указан в `.nvmrc`).

```bash
nvm use
npm ci
npm run dev
```

Откройте адрес, который покажет Vite. Для production-сборки:

```bash
npm run build
npm run preview
```

## Возможности

- Создание задачи с датой, необязательными временем и описанием.
- Выполнение, удаление и отмена последнего удаления в течение пяти секунд.
- Редактирование названия и описания прямо в карточке: Enter сохраняет название, Ctrl/Cmd+Enter — описание, Escape отменяет правку.
- Перенос через кнопку с календарём или перетаскивание за маркер слева на день текущей недели.
- Выбор дня сохраняется при обновлении страницы в текущей вкладке.
- Погода по приблизительному расположению IP. Сбой сервиса не мешает задачам; через восемь секунд ожидание прекращается.

## Хранение и ограничения

Задачи сохраняются в `localStorage` под ключом `dayline-tasks-v1`. Данные остаются в текущем браузере и на текущем адресе сайта; между устройствами они не синхронизируются. Очистка данных браузера удаляет задачи.

Сохранённый список проверяется до использования. Повреждённые или недоступные данные не перезаписываются. При сбое записи изменения остаются в памяти вкладки; предупреждение предлагает повторить сохранение. Пока сохранение не удалось, обновление или закрытие вкладки потеряет эти изменения.

Последовательные действия в нескольких вкладках учитывают актуальный список и синхронизируются через `storage`. Строго одновременные записи в разных вкладках не являются атомарной транзакцией: действует ограничение `localStorage` — последняя запись может победить. Для этого масштаба сервер и отдельная база данных не требуются.

Дата и просрочка определяются в часовом поясе устройства. Без времени задача становится просроченной на следующий день. Создание и перенос на прошедшую дату запрещены.

## Проверки

```bash
npm run check       # форматирование, Vitest, TypeScript и сборка
npx playwright install chromium firefox webkit
npm run test:e2e    # Chromium, Firefox, WebKit, мобильные 320 и 375 px
```

Проверки покрывают основной жизненный цикл, редактирование, перенос, клавиатуру, сохранение, ошибки хранилища, работу вкладок и длинные тексты. Погодные сервисы в тестах подменяются предсказуемыми ответами.

CI запускается для push в `main` и pull request. Публикация настроена владельцем в Vercel через подключённый GitHub-репозиторий: push в `main` запускает автодеплой. Параметры проекта Vercel: **Framework Preset — Vite**, **Build Command — npm run build**, **Output Directory — dist**, **Node.js — 22.x**. Сборка использует корневой `base: '/'`. GitHub Actions выполняет только проверки.

Автодеплой Vercel работает независимо от CI; перед отправкой изменений нужно выполнить локальные проверки. Публичная ссылка и наблюдаемый статус публикации фиксируются в `docs/verification.md`.

## Использование AI

Codex использован для аудита кода и пользовательских сценариев, подготовки плана, реализации доработок и написания проверок. Результат проверен сборкой, автоматическими тестами и просмотром в браузере. Другие AI-инструменты здесь не заявляются.

Ключевые решения: сохранить небольшой клиентский проект; хранить задачи локально; обрабатывать ошибки явно; оставить перетаскивание дополнительным способом к доступной форме переноса. Backend, авторизация и облачная синхронизация не входят в задание.

## Структура

- `src/components` — интерфейс, доступные диалоги и карточки.
- `src/hooks` — React-состояние, погода и перетаскивание.
- `src/utils` — проверка данных, операции хранения и локальные даты.
- `tests/e2e` — браузерные сценарии.

Сценарий демонстрации: [docs/demo.md](docs/demo.md). Для повторной записи запустите `npm run preview`, затем в другом терминале `npm run demo`. Видео и снимки появятся в `artifacts/` (не входят в Git). Погодные ответы при записи подменяются демонстрационными, задачи создаются в отдельной браузерной сессии.
